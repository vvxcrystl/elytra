# ts-rust compiler comparison — October 14, 2026

On branch `feat/ts-rust`, replacing the existing checker with [pingdotgg/ts-rust](https://github.com/pingdotgg/ts-rust) reduced the median full type-check time from **2.203 s to 0.126 s (17.46× faster)**. An unchanged production build with warm caches fell from **2.143 s to 1.541 s (28.1% less time)**. These are local development/build measurements; this change does not alter application request performance.

| Workload | TypeScript 5.9.3 | tsc-rs 0.7.0 | Speedup | Time saved |
| --- | ---: | ---: | ---: | ---: |
| Full check, incremental disabled | 2.203 s | 0.126 s | 17.46× | 94.3% |
| Unchanged incremental check | 0.855 s | 0.072 s | 11.86× | 91.6% |
| Unchanged production build, warm caches | 2.143 s | 1.541 s | 1.39× | 28.1% |

## Method

Each cell is the median of seven successful runs after one untimed warmup per compiler and scenario. Runs were sequential, alternating compiler order each round. Compiler timings include Node launcher startup and exclude the shared initial `next typegen`. Both checks used the same `tsconfig.json`, `--noEmit`, default compiler thread counts, and the same 150 project files, including generated Next route types. The script verifies matching project file lists and records a source-content hash. Each compiler includes its own standard-library declarations: 709 total input files for TypeScript and 719 for Rust. Both reported zero type errors. This comparison measures the adoption of Rust's TypeScript 7.1.0-dev checker from the project's existing TypeScript 5.9.3; it does not isolate the implementation language from compiler-version differences.

Full checks use `--incremental false`; they start fresh compiler processes but do **not** evict the operating system's filesystem cache. Incremental checks warm a separate temporary build-info file for each compiler, make no source edits, and remove those files afterward. They do not establish latency after an edit.

Build timings compare the original `next build` workflow (Next's built-in TypeScript checker) with `node scripts/build.mjs` (route generation, Rust check, then Next build). Both use the same current source, and warm their own compiler caches before measurement. Turbopack's existing production cache is retained. These are complete **warm** builds, including prerendering and standalone output; they do not establish clean-install or cold-build performance. Builds use an in-memory database and disable demo seeding. No other validation jobs ran concurrently with the benchmark.

Host: Linux x64, AMD Ryzen 7 7700, 16 available logical CPUs, approximately 30.4 GiB RAM, Node 26.10.0, Next 16.4.0. The baseline source revision is `6c25d7e`, with this branch's compiler integration applied to both cases. Raw samples, successful command outputs, hashes, execution order, and environment details are in [the JSON report](2026-10-14-ts-rust.json). Times can change with host load, hardware, project size, and cache state.

## Integration and validation

`npm run typecheck` generates current Next route types and runs `tsc-rs`. `npm run build` runs the same preparation and Rust check before launching Next's production build, setting a process-local flag to skip the duplicate built-in check. The flag is set only after the Rust command exits successfully. TypeScript remains installed for editor support, `typecheck:tsc`, and direct `next build` invocations.

Both type-check commands, ESLint, and all 16 production builds in the benchmark passed. A temporary `string = 123` fixture produced TS2322 in both compilers; the Rust build wrapper rejected it before bundling, and direct `next build` also rejected it. The fixture was removed after validation.

## Reproduce

```sh
npm ci
npm run typecheck
npm run typecheck:tsc
npm run bench:typecheck -- --runs 7 --build --output /tmp/elytra-ts-rust.json
```

Keep optional npm dependencies enabled, because `tsc-rs` supplies its executable through a platform package. Omit `--build` to measure only full and unchanged incremental checks. The benchmark refuses to report results if a command fails or the compilers select different project files. It clears `GOPORT_*` overrides and uses default Rust settings. Production build measurements update `.next` artifacts; avoid running other builds or benchmarks concurrently.
